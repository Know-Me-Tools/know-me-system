# Design: UAR knowledge strategy document

## Document architecture

The README proceeds from decision to evidence, then defines the common artifact
and loop model before specializing placement for mobile, desktop, and web. It
closes with synchronization, governance, licensing, evaluation, delivery,
rejected alternatives, open decisions, and source evidence.

The accompanying research package retains the audit trail that would otherwise
make the README unreadable: research plan, source registry, evidence graph,
claim citations, contradiction resolutions, synthesis report, and manifest.

## Governing distinctions

- Evidence corpus, Karpathy wiki, and episodic traces are distinct authorities.
- Canonical artifacts synchronize; derived indexes rebuild against a declared
  model binding.
- UAR semantics are shared, while process placement varies per platform.
- Wiki promotion and executable skill release are separate human-gated actions.
- Current source outranks stale future-work prose for implementation status.

## Verification boundary

Verification is documentary: Markdown structure and links, JSON validity,
evidence traceability, contradiction handling, no-code diff scope, KBD progress
invariants, and sycophancy screening. Runtime claims remain explicitly
uncertified unless backed by existing repository evidence.
